# Client behavior sources

Where each client behavior the input, menu and dropdown fakes simulate comes from. A rule is `confirmed` when
Blizzard's Lua shows it; the source column then gives `path:line` relative to `mirror/gethe/<branch>/` under the
testkit home (fetched by `tools/fetch.sh`). A rule is `assumed` when no Lua shows it; the source column then names
the warcraft.wiki.gg page that supports it, or says "no source". Every `assumed` rule has a test whose name ends in
`_assumed`. Rows describe the client. The kit follows them except where a verdict says "kit choice" (M13).

Every Blizzard `path:line` is for these Gethe/wow-ui-source commits, the ones the mirror held when the rows were checked
(each mirror's `COMMIT` file, written by `tools/fetch.sh`). A later fetch moves a mirror to its branch's newest
commit, so lines may drift there; read a cited line at its pinned commit.

The kit has these known gaps, which may not be the only ones:

- S5: an `AddButton` to a hidden list that is not being built is dropped; the client appends it there, where only
  `numButtons` sees it until that list's next Initialize or Toggle clears it (`framexml/fakes/dropdown.lua`).
- S1, S16: the client indexes `button` past level 1 (Mainline `:1168`, Classic `:1107`) and, with no frame, at
  `:1065`/`:1004`, so a Toggle without one errors; the kit accepts a nil `button` (`framexml/fakes/dropdown.lua`).
- S16: `s:menu()` and `s:pick` start at level 1, so they report no menu while a list is shown above a closed level 1,
  and `s:menu()` stops at the first closed level, so open levels 1 and 3 read as level 1 alone (`scenario_menu.lua`).
- S13: a disabled entry's text does not get `colorCode` or `disablecolor` (Mainline `:484-490`), though both are
  written back into the caller's `info` (`framexml/fakes/dropdown.lua`).
- S11: opening a level renders every entry and sets the kit's `OnClick` and `OnEnter` on each pooled Button, so an
  addon's `SetScript` on `DropDownList<n>Button<i>` lasts only until that list next opens; the client's scripts come
  from the template once (`framexml/fakes/menu_frames.lua`).
- S17: `AddButton` does not check the entry from the frame's selected name, ID or value (Mainline `:633-648`, Classic
  `:568-583`), and `UIDropDownMenu_SetSelectedValue` stores the value without the client's `UIDropDownMenu_Refresh`
  (`framexml/fakes/dropdown.lua`).
- S14: the layout globals (`UIDROPDOWNMENU_MAXBUTTONS`, `_BUTTON_HEIGHT`, `_BORDER_HEIGHT`, `_SHOW_TIME`,
  `_DEFAULT_*`) and `OPEN_DROPDOWNMENUS` are not set (`framexml/fakes/dropdown.lua`).
- M4: a `SetEnabled` function is re-read on (re)initialize and before a pick, never on the client's 0.2 s poll.
- M10: `Menu.ModifyMenu` does not run a new hook at once on an already generated menu with that tag
  (`framexml/fakes/menu.lua`).
- D1: a held Shift is not read, since the kit has no key state (`framexml/fakes/menu_dropdown.lua`).
